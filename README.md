# 选个好职位

React + TypeScript + Vite 招考信息筛选器。当前为 2027 年国考职位数据：原始文件实际是 `data.xls`，含 4 张有效工作表、19,426 个职位、35,691 个名额。保留全部 27 个原始字段；空白 Sheet1 不参与导入，原文件保持不变。

## 运行与验证

```sh
npm install
npm run dev -- --port 5178
```

打开 http://localhost:5178 。已附带 `public/positions.json`，运行网站无需 Python。

```sh
npm test
npm run build
npm run preview
```

生产部署使用整个 `dist/` 目录，需一并部署 `positions.json`。

通过脚本构建和上传：

```sh
./run.sh build           # 仅构建，资源使用相对路径，支持 content/ 子目录
./run.sh build --upload  # 构建成功后上传到 s3://game/guo_2027/content/
python3 scripts/test_run_sh.py  # 模拟 npm/aws 验证脚本，不执行实际上传
```

上传使用 AWS CLI 的 `seastar` profile；本地构建不需要 Facebook 环境变量或 AWS 凭据。脚本不接受版本号或 debug 参数。

## 选岗功能

- **按我的条件**：本人最高学历、对应学位、毕业身份、政治面貌、基层工作年限、基层项目经历及性别。学历按原文枚举兼容，年限按最低要求匹配，政治面貌同时纳入不限职位。未填写项不参与排除。
- **按职位原文**：学历、学位、政治面貌、最低年限精确筛选；基层项目按原文包含关系筛选。切换模式会保留各模式独立填写的条件，未启用模式的条件不参与查询。
- **专业查询**：默认按学历层次选择专业目录条目，通过专业名称、代码、专业类和学科门类匹配。税务职位优先采用其专用分类；支持切换原文关键词搜索。不限专业按对应学历分段处理。
- **我的英语成绩**：在“按我的条件”中填写成绩即自动生效，此模式隐藏并忽略英语原文类型选项。四级、六级按710分制填写，可补充雅思、托福及专四／专八。明确门槛高于成绩的职位自动排除；填写最高学历后区分本科、研究生分段。留空表示未填写，0表示未参加／无成绩；替代证书未填、旧百分制、单项分数、例外和复杂条件保留待核对。详情展示英语核对理由。
- **英语要求**：按备注原文筛选四级、六级、专四、专八、雅思、托福、其他英语描述、明示不要求英语或未提及英语。可与地区、学历、专业等组合；详情保留分数、替代证书及学历分段原文。未提及不等于不限，提及某证书也不代表仅有该证书就可报考。
- **其他筛选**：省份多选（省份之间为“或”）、工作城市／区县下拉多选（先选省份，逐个添加地点，标签可单独移除；地点之间为“或”，与已选省份为“并且”）、部门、招录类别、考试类别、面试阶段专业能力测试、备注关注项。不同字段之间为“并且”。
- **原文提醒**：提取毕业届别、性别、外语、证书、服务期、户籍／生源、体能、工作安排与学习经历相关片段。列表提示、详情展开原文。
- **对比**：2—4 个职位，差异高亮、只看不同项、移动端横向滚动、对比职位导出。
- **收藏与备注**：收藏列表独立于搜索条件。备注自动保存，首次记录时自动收藏；取消收藏不会删除备注，再次收藏可恢复。筛选、个人条件、收藏及备注仅保存在本机浏览器。
- **导出**：导出当前全部匹配结果、全部收藏或对比职位，包含全部原始字段与备注，不限当前分页。启用专业目录筛选时另附匹配依据与目录来源链接。CSV 对公式起始字符做防护；用 Excel 的“从文本/CSV”导入并将代码列设为文本，可保留前导零。

## 资格匹配边界

这是初筛工具，不作最终报考资格判定。详情用“初步相符 / 不匹配 / 待核对”逐项展示已填写条件的核对理由。

明确、简单的届别及性别限制参与排除；未识别出的复杂表述、例外条款仍需人工核对。不能把未提及理解为不限，也不能以出现“应届”两字直接判定为应届专岗。项目经历命中后，其服务年限、考核结果等仍标为待核对。学历、专业的各阶段要求、年龄、证书及附加公告条件不自动完成全面判定。

专业目录共 2,600 个条目，覆盖教育部本科（2026）、研究生（2022）、专业学位领域（2025）、研究生历史目录及职业教育（2026年7月），另含税务系统2027年度53个专业类别。来源链接在页面中展示，原始文件及 SHA-256 归档在 `data/catalog/sources/` 和 `src/catalog-data.json`。

这是有目录依据的名称、代码与层级匹配，不使用模型猜测近义专业。先选择具体条目才启用查询。同名研究生专业、历史口径和无法自动解释的附加条件会保留为“待核对”；已识别出的明确排除和不相符的专业列举会过滤。未收录的专业可切换原文搜索；复杂学历分段和方向要求需人工确认。

重建目录：`python3 scripts/import_catalog.py`（使用已归档的 PDF 文本、HTML 和 DOCX；更新 PDF 时先通过 `pdftotext -layout` 重建同名文本）。导入器校验条目唯一性与关键专业代码。

“面试阶段无专业测试”只对应原表第 19 列，不代表没有专业科目笔试。数据为静态原表，不提供实时报名人数、竞争比、历史进面分数或自动报名。

## 更新数据

替换同结构的 `data.xls` 后执行：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm run data
npm run build
```

导入验证所有工作表的字段结构、职位代码、招录人数与唯一标识，记录来源表及行号、文件 SHA-256 和导入时间。界面导入时间显示北京时间，不作为官方发布时间。

目前界面、届别规则、偏好与备注存储键均对应 2027 年。换年度需同步更新这些配置、测试基准及收藏命名空间，不能只替换文件。收藏用“部门代码 + 职位代码”标识；同年度原表行重排不影响收藏。

## 查询性能

查询在 Web Worker 中执行，职位数据仅在线程初始化时传入，返回职位索引以减少传输量。输入合并等待 100 毫秒，旧请求结果按请求编号丢弃；更新期间显示查询状态并禁用结果导出。相同专业要求复用匹配结果，只保留当前专业的缓存，且设有条目上限。地区、学历等低成本条件先于目录匹配执行。

本机对 19,426 条数据的纯筛选计算测量：软件工程筛选首次约 51 ms，重复约 10–11 ms（优化前约 174–204 ms）；叠加杭州地区约 1–3 ms（优化前约 174–178 ms）。这些数值不含 100 ms 输入合并等待、线程通信与渲染，不代表所有设备的页面响应时间。四组优化前后职位 ID 与顺序逐项一致。生产构建已验证子目录下 Worker 加载与连续输入查询。

## 英语规则预处理与审计

`npm run prepare:english` 从职位备注提取英语考试门槛，生成按学历分支区分的分数、证书、AND/OR 规则，写入 `positions.json` 的独立 `englishRules` 字段。所有 27 个原始字段保持不变。`npm run data` 和 `npm run build` 均自动执行预处理；页面和查询线程使用同一份预处理规则，旧数据没有该字段时可回退到相同解析器。

审计文件 `data/english-rules-audit.json` 包含原文、结构化规则、无法识别的原因、职位 ID、来源工作表及行号。结构化完成率只是解析覆盖率，不是报考资格认定准确率。专四／专八的“良好、优秀”、其他外语资格、复杂例外等仍保留待核对；CET 合格描述没有明确现代分数时，不擅自换算成 425 分。证书未填写不会被当成未取得，结果卡片会说明缺少哪些信息。
